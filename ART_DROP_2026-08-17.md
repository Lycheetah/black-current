## ⭐⭐ THE FINDING — THE FILENAME IS THE NAME

The standing law is **DO NOT INVENT SHIP NAMES; Mac names the ships from the art
he generates.** This drop is that naming, already done. Every root filename is
`<FACTION> <CLASS>`. Nothing needs christening. The ingest's only job is to
**read** his names, never to author one.

**⛔ THEREFORE: the ingest is a PARSER, not a generator.** A filename that does
not parse is reported as `UNRESOLVED` and left alone. It is never "best
guessed" — a guess at a name *is* an invented name, and it splits the roster.

## THE SURGICAL ATTACK — WHAT INGEST ACTUALLY MEANS

**⛔ DO NOT INVENT A SECOND ART PATH.** The pipeline already exists and is proven:
`scripts/build-art-manifest.py` and `scripts/extract-node-points.py`, writing
`clean/` siblings and `art/manifest.json`. The drop goes through *that*.

Order of operations, each step witnessed before the next:

1. **Parse-only dry run.** Walk all 106 files, emit the `{file → faction, class,
   tier}` table with an `UNRESOLVED` column. **Write nothing else.** Mac reads
   the table and rules on the ambiguous rows. This is the whole first step —
   a parser that writes no assets cannot corrupt anything.
2. **Copy, don't move.** The Downloads folder stays intact. A destructive
   ingest with no undo is not an ingest.
3. **Through the existing keyer.** ⭐ Recorded law: *a key only works when the
   background colour is absent from the subject.* Against black, distance-to-bg
   IS brightness, so a naive keyer eats dark ships. The generator gives **three**
   backgrounds, not one — **probe each file, never trust the prompt.**
4. **Mount points are mount-local only.** `#00FF00` is the machine-readable
   mount marker AND the engine's own green. ⛔ A whole-bitmap colour sweep
   cannot tell a marker from paint. Strip mount-local.
5. **A core node wears no sprite.** Several sockets on one image = a HULL, not a
   part. The caterpillar bug was filing eight of those as `core`. Do not repeat it.
6. **Count usable ≠ count drawable.** The last run was 268 sliced → 136 usable →
   99 drawable. Report all three numbers or the receipt is a lie.

## THE SHIP DESIGN TOOL — HIS ACTUAL ASK

> *"i want a proper ship design tool"*

**⭐⭐ THE ONE LAW THAT DECIDES IF THIS WORKS: THE EXPORT FORMAT MUST *BE* THE
FILE FORMAT.** If what the tool exports needs any hand-massaging before the game
can load it, a second ship format now exists and the roster is split. The tool
emits exactly the `FLEET_HULLS` entry shape and nothing else:

```
{ id, frame, mark, scale, color, primaryWeapon, secAbility, nodes[] }
```

**Where it lives:** a third tab in `js/bay.js` — Build / Export / Import.
Per the codebase idiom every new capability is a **new self-owning file** that
owns its own input, HUD, DOM and data, so `engine.js` is not touched. Two seats
are live on this repo; `engine.js` is the file most likely to be corrupted by
both editing at once.

**Why it is now urgent:** `FLEET_HULLS` is **empty** — all premade hulls were
removed on his instruction. `ORDER` is derived from it, `cycle()` is guarded and
banners *"No hulls authored yet"*. Until the tool exists there is no way to put a
ship back in. **The tool is not a nicety; it is the only remaining door.**
